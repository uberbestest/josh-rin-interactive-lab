    03 / The argument

    A trustworthy past is not a permission lease.

    Two worlds can deliver the exact same authentic snapshot. In one, permission remains valid. In the other, it is revoked before execution. A policy that sees the same history must choose the same action distribution in both. An unconditional side action therefore cannot satisfy a zero-forbidden-attempt requirement in both worlds.

    Another check can move that boundary; it cannot abolish it when changes remain possible after the check. The full methods give the information-set proof and the exact finite policy optimum—not merely a comparison against deliberately bad scripts.

    Do not charge an agent for an impossible contract. A low completion score can reflect an interface’s safety ceiling. Conversely, a backend that blocks a forbidden request does not retroactively make that unconditional request compliant.

    Three interfaces. One optimizer.

    Snapshot: read current permission and version, then decide later. Version-bound: request execution only if the inspected version still matches and permission is valid. Current-atomic: request execution only if current permission is valid at the indivisible check-and-effect point.

    The last two requests are both safe under their stated contracts. Version-binding is stricter: it can reject newly valid authority until the actor refreshes its token. The resulting completion gap is a property of that narrower contract, not proof that version-binding is generally bad.

    We changed the interface, not intelligence. The atomic mechanism is stipulated trusted infrastructure. Breaking its atomicity breaks its guarantee. The fault-injection controls make that dependency visible.
