When the warning went away.

Does an agent need explicit warnings about misleading history to avoid duplicating already-completed work? We removed three trap-specific warning sentences, but kept the same evidence and authorization contract. The model still finished every assigned case safely.

Observed result · four predeclared arms

Removing the warning did not change the outcome here.

Both jobs A and B were authorized. One was already committed, but neither finalized. The model had to read job-specific authoritative receipts, commit only the absent job, and finalize both. Combined receipts included misleading historical ABSENT information about the other job. Target-only receipts did not. The explicit-warning condition additionally told the model not to be fooled by that nested history; the contract-only condition omitted the three warning sentences while preserving the actual operational rules.

Observed model behavior

The action followed the targeted receipt.

Across 80 recorded service actions, there were 32 receipt checks, 16 justified commits, and 32 finalizations. The already-committed job was never committed twice; the absent job was committed once after its own authoritative receipt. All 16 final reports agreed with the service traces.

What remains open

The contract stayed strong.

The contract-only condition still required authoritative, target-matched evidence. The model never faced a changed misleading cue, weaker authority contract, unfamiliar domain, or actual ambiguity about the available receipt. The warning removal also changed text length and combined user and tool wording changes.

Method, provenance, and limits

The frozen 2 × 2 × 2 design crossed warning style, receipt scope, and precommitted job, with two fresh assignments per full cell. The first eight-case order was followed by its reverse; this was counterbalancing, not randomized sampling. Each session requested gpt-6.2-astra, medium reasoning, up to eight sequential API requests, up to 4,096 output tokens per request, no repair turns, and store=false. No trial was replaced or rerun.

The frozen plan SHA-256 is 825adb786bf1b854c4e313020c4439e85514c6719cfb1976f369a3dfdbd402db; the plan and six-file runtime freeze SHA-256 is 1908ce1cd47677f277f62c1d96eea093de6935aa02659cbb7bbbfc19e61f0667. Every case passed the predeclared service-state criterion. The extra warnings were removed as one bundled intervention—not as separate tests of user versus tool instruction placement.

Recorded usage: 45,414 input tokens, 2,958 output tokens, zero reported reasoning tokens, and 96 of 96 successful responses. The provider-reported usage and frozen price table produce the $0.481632 estimate; this is not invoice verification. There were zero blocked or resource-limited cases, zero unresolved provider requests and zero unresolved reserves. No encrypted reasoning output items appeared, so replay of such items is not established.

Interpretation: Safe behavior under the exact authority-bound service contract survived removal of the extra trap-specific warnings across these 16 authored cases. This does not establish a general reliability rate, a mechanism, immunity to new deceptive cues, or real-world policy suitability. The next informative experiment would change the conflict or evidence uncertainty, not simply repeat this ceiling case.
