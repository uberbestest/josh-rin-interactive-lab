# Round 09 separately authored continuation challenges

This is a bounded deterministic engineering evaluation of a controller. It is not a new sample of native model trials or a serving-snapshot comparison.

The challenge author read the inherited service contract and engine to preserve the public semantics. The author did not inspect the candidate source or candidate development results before freezing these assignments. This is separate authorship within one lab, not external replication or a guarantee of statistical independence. The parent supplied the intended algorithm class and requested failure mechanisms.

## Frozen selection

Twenty-four authored public configurations cover scheduling during receipt delay, paid-query budget loss, free-query time loss, shared-budget priority tradeoffs, known-present and known-absent jobs, exact action caps, inclusive deadlines, multiple possible readiness times, and unbounded or resource-impossible controls. Every declared original-delivery/readiness combination consistent with initial authoritative evidence is enumerated. No assignment is selected or removed based on candidate performance.

Configs are authored and hashed before reference-oracle labels are computed. The reference oracle remains evaluator-only. It does not supply the candidate actions, expected values or hidden worlds. The candidate's source is frozen separately before any challenge execution.

## Outcomes to keep distinct

1. Whether a trajectory attempted an unsupported commit or finalization.
2. Mechanical finalized-job count and actual duplicate effects.
3. Achieved safe utility relative to the initial public-information guaranteed utility.
4. Whether each selected action retained the current attainable guarantee across all public-consistent outcomes.
5. Whether favorable hidden outcomes increased the final completion count beyond the initial guarantee.
6. Whether terminal reporting accurately preserves unknown delivery or a resource barrier.

Initial utility zero is a legitimate control. An honest stop can preserve that value but is not a positive guaranteed completion. Conversely, a controller may finish a job in a favorable hidden world that could not be guaranteed initially. Those mechanical outcomes must not be relabeled a stronger initial guarantee.

## Transport evidence boundary

The canonical engine response contains `local_status`, including authoritative original receipts. If a transport adapter changes only the displayed top-level job/status while leaving that canonical status available, the actor can legitimately learn target evidence from the local status or a subsequent `status` command. A success in that arrangement does not demonstrate that top-level receipt-header validation was the sole source of safe behavior.

Use separate records for canonical responses and displayed substitutions. An independent trace check replays canonical mechanics, evidence requirements, counters, deadlines and action limits. A transport claim additionally needs the actor-observed response record. The challenge configs themselves use identity transport; inherited Round 08 mismatch cases are a distinct comparison.

## Limits

The contract fixes two jobs, stable authorization, immutable original-write receipts, a synthetic discrete clock, non-idempotent writes and a small action cap. Passing these challenges establishes bounded controller behavior. It does not establish broad model superiority, retained model learning, a production integration, buyer willingness to pay or security-bounty eligibility.
