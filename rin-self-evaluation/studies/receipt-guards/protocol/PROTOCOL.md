## Response fault and provenance

The inherited correct client never returns the wrong job. The two mismatch cases therefore use a declared **one-shot response-substitution adapter**, after the first actual B receipt completes. The canonical output must be B PENDING with NOT_ESTABLISHED coverage, known A COMMITTED, and no B exactly-one evidence. Only three top-level fields in the shown JSON change: `status` becomes COMMITTED, `job` becomes A, and `coverage` becomes AUTHORITATIVE_FINAL. The transaction and complete nested local status are unchanged. No delivery, resource counter, canonical observation, engine belief, event hash, or physical state is edited.

This synthesized misbound header agrees with A's already-known receipt; it provides no valid new B evidence. Raw client stdout and the exact shown stdout are separately retained with byte counts, hashes, changed-field records, and action binding. All later responses are authentic. A later recovery witness is conditional on this one-shot fault bound and trusted subsequent responses; it is not a guarantee against indefinite transport corruption.

The canonical engine still scores its own correctly recorded observations. In these specific mismatch cases, canonical B PENDING and shown A COMMITTED both leave B without exactly-one evidence, and A's fact was already known. This agreement makes the inherited unsafe-action classification applicable to the target operation. It would not justify using the engine unmodified for arbitrary response corruption.

## Independent feasibility checks

Before the main matrix, author simple contingent schedules from public facts and validate their resource arithmetic independently of the reference optimizer. Then apply those schedules to each public-consistent hidden world with the inherited transition function. These are explicitly counted instrument/witness checks, not part of the 64 helper executions. Initial-policy witnesses establish canonical-service feasibility only: they do not execute the adapter. In particular, waiting before the first B query would move the mismatch-labeled initial witness outside the frozen adapter's required PENDING exposure. Post-pending recovery witnesses model discarding the first pending/misbound response and receiving authentic later responses; adapter execution is validated separately.

For known-A pending/mismatch cases, after a first pending receipt ends at tick 2 with five uses, a second authentic B receipt ends at 4. If B is absent: commit at 5, finalize at 6, then finalize A at 7. If B is present: finalize B at 5, then A at 6. These finish both without unsafe actions. The frozen guarded helper itself only stops; it does not take this recovery route.

For the no-decoy case, a correct initial policy waits until tick 2 before the first B receipt, which ends at 4; the worst both-absent path finishes B at 6 and A at 10 using all six uses. An immediate pending query makes the worst-case route require seven total uses despite a six-use credential. This is a resource effect of the control's uncertainty, separate from the subsequent readiness bug.
