## Receipt-output intervention

`combined` retains the original complete receipt observation.

`target` changes only receipt responses containing `local_status.jobs`: keep the entry for the requested job and remove the other job entry. Keep the selected entry byte-equivalent in content, preserve all top-level observation fields and all other `local_status` fields, and use the same deterministic JSON serialization. If a receipt response has no such mapping, preserve that response unchanged under the frozen renderer rule.

All `status`, `commit`, `finalize`, `wait` and `finish` outputs retain their original response shape and content; none receives the projection. A full status read remains free, begins every task, and stays available throughout. Initial facts, prior observed evidence, costs, deadlines, objective, action semantics, report format and transport permissions stay constant. In particular, this study does not forbid orchestration wrappers, force a parser, provide the recovered helpers to participants, or add a parsing warning. Those changes would alter the behavior being investigated.

The exact common contract and checklist requirement are inherited. After normalizing run identifier and client prefix, all native prompts match the Round 06 checklist prompt. Receipt scope is an implementation setting, not additional prompt guidance.

Removing non-target receipt details also shortens the response and reduces repeated exposure to already-known facts. This is a **response-scope/content-length intervention**, not a pure visual-layout manipulation. Any native difference could involve those bundled changes; it does not uniquely identify a cognitive entity-binding mechanism. The deterministic recovered-helper counterfactual can isolate the particular whole-response predicate more narrowly.

A focused-arm actor may request a free full status after a receipt or rely on earlier full outputs. Preserve such behavior. Analyze by assigned scope without excluding, reassigning or censoring those runs.
